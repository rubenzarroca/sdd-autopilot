# Mission Briefing: git-operator

## Objective
Commit all implementation changes to the feature branch, push to remote, and open a PR with machine-readable metadata in the description. Transition pr_created→merged is triggered by human merge action; this agent only transitions to pr_created.

## Model
sonnet-4.6 (git commands are mechanical)

## Receives
```
required:
  feature_name:     string
  worktree_path:    string   # path to the feature worktree
  base_branch:      string   # branch to PR against (default: main)
  feature_description: string
optional:
  spec_path:        specs/{feature}/spec.md      (for PR body)
  review_summary:   string                        (from REVIEW_RESULT.summary)
max_input_tokens: 1000
```

## Produces
```
pr:
  title:   "[SDD] {feature_description}" (max 72 chars)
  body:
    - ## Summary: 2-3 bullet points from spec.md overview
    - ## Spec: link to specs/{feature}/spec.md
    - ## Tasks: count of tasks completed
    - ## Verification: PASS (from VERIFICATION_RESULT)
    - ## Review: summary from REVIEW_RESULT.summary
    - Footer: "Generated by SDD Autopilot v2"
  labels:  ["sdd-autopilot"]
  draft:   false
output:
  pr_url:     string
  diff_stats: string   (lines added/removed)
```

## Execution sequence
```
1. run_shell: git -C {worktree_path} add -A
2. run_shell: git -C {worktree_path} commit -m "feat({feature}): {feature_description}\n\nGenerated by SDD Autopilot v2"
3. run_shell: git -C {worktree_path} push -u origin {branch_name}
4. run_shell: gh pr create --title "..." --body "..." --base {base_branch}
# No transition_state call needed: feature is already in pr_created (adversarial-reviewer did reviewing→pr_created on APPROVE)
# pr_created→merged is triggered externally when the human merges the PR
```

## Success criteria
- PR URL returned in output
- PR description contains all required sections
- Commit message follows conventional commits format
- No untracked files omitted from commit

## Failure modes
```
ESCALATE:
  trigger: push rejected (permissions, protected branch, remote conflict)
  action:  emit ATTENTION_REQUIRED signal with {action: "ESCALATE", reason: exact error}; do not force-push; halt
MERGE_CONFLICT:
  trigger: branch diverged from base
  action:  attempt rebase; if rebase fails, emit ESCALATE; do not force-push
```

## Decision heuristics
- Commit message too long → truncate feature_description at 50 chars for subject line
- PR body sections missing data → use placeholder "[data unavailable]" rather than omitting section
- Draft vs ready → always ready (not draft); if review found warnings, add "[warnings present]" to title

## Context budget
```
receives:  feature metadata (≤500t) + spec overview (≤300t) + review summary (≤200t) = max 1000t
```

## Allowed transitions
```
pr_created → merged   # triggered by human merge; git-operator does not execute this
```
